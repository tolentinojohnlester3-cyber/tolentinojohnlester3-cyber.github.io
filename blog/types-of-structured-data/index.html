Types of structured data you can put on a website

Structured data is machine-readable markup that tells search engines what your page is about — a product, a local business, an FAQ, a recipe, or a person. This guide lists every major Schema.org type worth knowing, when to use it, and how to implement it with JSON-LD.

What structured data is

Structured data is a standardized vocabulary — mostly Schema.org — wrapped in code so crawlers can read entities on your page without guessing from HTML alone. You describe things like:

  • Who wrote the article (Person, author)
  • What the business sells (Product, Offer)
  • Where a store is located (LocalBusiness, PostalAddress)
  • Questions on an FAQ page (FAQPage, Question, Answer)

Structured data does not guarantee rich results or higher rankings. It makes your content eligible for enhanced search features and helps AI systems understand entities, relationships, and page purpose. Google recommends JSON-LD in a <script type="application/ld+json"> block.

Rule of thumb: Mark up what is visibly true on the page. If a price, rating, or address is not shown to users, do not put it in schema. Misleading markup can trigger manual actions.

JSON-LD, Microdata, and RDFa

FormatHow it worksBest for
JSON-LD Separate JSON block in <head> or <body> Most sites — Google’s preferred format; easy to maintain
Microdata HTML attributes like itemscope, itemprop Legacy WordPress themes; harder to refactor
RDFa HTML attributes with RDF vocabulary Rare today; some enterprise CMS setups

On WordPress, plugins like Rank Math and Yoast output JSON-LD automatically. On static sites and custom builds, I hand-write JSON-LD in each template — this portfolio uses @graph blocks on every page.

Site-wide structured data

These types describe your site as a whole. Most professional sites should have at least WebSite, Organization or Person, and page-level WebPage markup.

Schema typeUse whenKey propertiesRich result?
Organization Company, brand, or agency site name, url, logo, sameAs, contactPoint Knowledge panel
Person Portfolio, author, consultant, creator name, jobTitle, image, sameAs, worksFor Entity trust
WebSite Every site name, url, publisher, optional SearchAction Sitelinks search box
WebPage Every indexable URL name, url, description, isPartOf —
ProfilePage About / bio pages mainEntity → Person —
AboutPage About us pages Subtype of WebPage —
ContactPage Contact pages Subtype of WebPage —
CollectionPage Blog index, category hubs mainEntity → ItemList or Blog —
BreadcrumbList Any page with visible breadcrumbs itemListElement with ListItem positions Breadcrumbs

Example: Organization + WebSite

<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@graph": [
    {
      "@type": "Organization",
      "@id": "https://example.com/#organization",
      "name": "Example Co",
      "url": "https://example.com/",
      "logo": "https://example.com/logo.png",
      "sameAs": [
        "https://www.linkedin.com/company/example",
        "https://www.facebook.com/example"
      ]
    },
    {
      "@type": "WebSite",
      "@id": "https://example.com/#website",
      "url": "https://example.com/",
      "name": "Example Co",
      "publisher": { "@id": "https://example.com/#organization" },
      "potentialAction": {
        "@type": "SearchAction",
        "target": "https://example.com/search?q={search_term_string}",
        "query-input": "required name=search_term_string"
      }
    }
  ]
}
</script>

Use these on articles, guides, news, FAQs, and how-to content. Match the schema type to the actual page format.

Example: BlogPosting + FAQPage

{
  "@type": "BlogPosting",
  "headline": "How to fix sitemap errors in GSC",
  "datePublished": "2026-09-14",
  "author": { "@type": "Person", "name": "John Lester Tolentino" },
  "image": "https://example.com/featured.jpg",
  "publisher": { "@id": "https://example.com/#organization" }
}

Every blog post on this portfolio uses BlogPosting inside an @graph, plus matching FAQPage when the article has an FAQ section — like layers of SEO and this guide.

Local and business schema

Local schema tells search engines your business name, address, phone, hours, and service area. Use the most specific subtype that fits.

LocalBusiness

Base type for any physical or service-area business with a local presence.

Restaurant

Food service — menus, cuisine, reservations.

Store / ClothingStore

Retail locations with products and opening hours.

MedicalBusiness

Clinics, dentists, hospitals — often paired with Physician.

ProfessionalService

Lawyers, accountants, agencies, contractors.

HomeAndConstructionBusiness

Plumbers, electricians, HVAC, builders.

Supporting typePurpose
PostalAddressStreet, city, region, postal code, country
GeoCoordinatesLatitude and longitude for maps
OpeningHoursSpecificationDays and times open — must match visible hours
ContactPointPhone, email, contact type, languages
areaServedCity, region, or country served
hasMapLink to Google Maps or equivalent
aggregateRatingOnly if real reviews are displayed on page

For multi-location brands, create one LocalBusiness entity per location page — not one block listing every branch on the homepage unless all addresses are visible there.

The @graph pattern (recommended)

Instead of separate unrelated JSON-LD blocks, connect entities with @id references inside one @graph array. Benefits:

  • One source of truth for Organization / Person
  • Clear relationships: WebPage → isPartOf → WebSite
  • BlogPosting → author → Person → publisher → same Organization
  • Easier debugging in Rich Results Test
{
  "@context": "https://schema.org",
  "@graph": [
    { "@type": "Person", "@id": "https://example.com/#person", "name": "Jane Doe" },
    { "@type": "WebSite", "@id": "https://example.com/#website", "publisher": { "@id": "https://example.com/#person" } },
    { "@type": "BlogPosting", "author": { "@id": "https://example.com/#person" }, "isPartOf": { "@id": "https://example.com/#website" } }
  ]
}

Testing and rich result eligibility

After adding markup, validate before deploy:

  • Google Rich Results Test — shows eligible rich result types
  • Schema.org Validator — checks syntax and required fields
  • Google Search Console → Enhancements — monitors FAQ, Product, Video, etc. after indexing

Google supports a subset of Schema.org for visual rich results. Types like Organization and Person may not produce a visible snippet but still help entity understanding and AI Overviews. See Google’s structured data gallery for the current list.

Common mistakes

  • FAQ schema on pages with no visible questions and answers
  • Review stars without real reviews on the page
  • Duplicate conflicting JSON-LD from theme + SEO plugin + custom code
  • Marking every page as Article when it is a product or contact page
  • Using LocalBusiness on a site with no physical location or service area
  • Broken @id references pointing to URLs that do not exist

FAQ

What is the best format for structured data?

Google recommends JSON-LD inside a <script type="application/ld+json"> block. It keeps markup separate from HTML and is easiest to maintain on WordPress, static sites, and SPAs.

Does structured data improve rankings?

Not directly. It helps search engines understand your content and can unlock rich results, which may improve click-through rate. Quality content, crawlability, and links still drive rankings.

How many schema types can one page have?

Multiple types are fine when they describe different visible elements — for example WebPage + BlogPosting + FAQPage + BreadcrumbList on one article. Connect them with @graph and @id.

What is the difference between FAQPage and QAPage?

FAQPage is for a list of questions you authored (like this section). QAPage is for a single user-generated question with one or more answers, such as a forum thread.

Do I need structured data if I use WordPress SEO plugins?

Plugins like Rank Math and Yoast add baseline Article, Organization, and breadcrumb schema automatically. You may still need custom JSON-LD for FAQs, HowTo steps, products, events, or multi-entity @graph setups.

Where can I see all Schema.org types?

The full list lives at schema.org/docs/full.html. For Google rich results, cross-check with the search gallery — not every type produces a visual enhancement.
