How to clone your website to a new site using cPanel

Cloning copies an existing site — files, database, theme, plugins, and content — onto a new domain. On a cPanel server you can do this in minutes with Softaculous Clone (same hosting account), or by zipping files and exporting MySQL when the new site lives on a different cPanel or host.

Which clone method to use

Use this only on sites you own or are authorized to move. A clone is a full copy, not a redirect. The original site stays online unless you take it down later.

Pick the path that matches where the new site will live:

Method 1 — Softaculous CloneMethod 2 — Files + database
Best forNew domain or subdomain on the same cPanel accountNew cPanel, new host, or a site Softaculous does not manage
Time2–10 minutes20–45 minutes
DatabaseCreated automaticallyYou create it, then import the .sql dump
URL rewriteSoftaculous updates most WordPress URLsYou run a serialized search-replace
Risk to originalLow — source is not overwrittenLow if you export copies, not move files
Softaculous Staging is related but different. Staging copies the site to a test URL and can later push changes back. Clone creates a second independent site. Use staging for experiments; use clone for a new brand, country domain, or a spare copy.

Before you start

Have these ready so you are not stuck mid-copy:

  • cPanel login for the source account — usually https://yourdomain.com:2083
  • The new domain added to cPanel — addon domain, parked domain, or subdomain, with document root created
  • DNS pointed (or a hosts-file test) — the new hostname should resolve to the destination server before you test in a browser
  • Enough disk space — a clone needs room for a second copy of files plus a second database
  • A note of the source database name — in WordPress, open wp-config.php and copy DB_NAME, DB_USER, and DB_PASSWORD

If the new domain is not on this account yet, add it first: cPanel → Domains → Create A New Domain. Leave “Share document root” unchecked so the clone gets its own folder (often public_html/newsite.com or a sibling of public_html).

Need a blank WordPress install instead of a copy? Use How to install WordPress in cPanel, then import content separately.

Method 1 — Softaculous Clone (same cPanel)

This is the fast path when both domains sit on one hosting account and WordPress was installed (or imported) through Softaculous.

Step 1 — Log in to cPanel

Open your cPanel URL, enter the username and password from the welcome email, and complete 2FA if it is enabled. You should land on the Jupiter dashboard: left sidebar, Search Tools bar, and grouped cards for Files, Databases, Domains, and Software.

Step 2 — Open Softaculous and find the live install

In Search Tools, type Softaculous and open Softaculous Apps Installer. Go to the WordPress script page, then open Current Installations (sometimes labeled under the user icon → All Installations).

You should see a row for the source site. On the right, click Clone — not Upgrade, not Remove, not Staging unless you specifically want a push-back workflow.

Step 3 — Choose the new domain

Softaculous asks where the copy should live:

  • Choose Domain — pick the new domain or subdomain. It must already exist in cPanel.
  • In Directory — leave blank to clone to the root of that domain (https://newsite.com/). Enter a folder name only if you want https://newsite.com/copy/.
  • Database name — leave the auto-generated name unless your host forces a prefix.

Do not point the clone at the same directory as the original. That overwrites the live site.

Step 4 — Finish and open the new site

Click Clone Installation (or Clone now). Softaculous copies files, creates a new MySQL database, imports the data, and rewrites WordPress home/siteurl to the new hostname. Time depends on site size — a brochure site is seconds; a large uploads folder can take several minutes.

When it finishes, save both URLs: the public site and /wp-admin/. Log in with the same WordPress username and password as the source. Then spot-check the homepage, a blog post, and the media library.

Skip to URL replace if some links still point at the old domain (menus, widgets, page builders, and plugin options often store extra URLs). Then run the after clone checklist.

Method 2 — Files and database (new cPanel or new host)

Use this when the new site is on another cPanel account, another server, or Softaculous does not list the install. You copy two things: the website files and the MySQL database. Missing either half produces a broken clone.

Step 5 — Zip the source files in File Manager

On the source cPanel: Files → File Manager. Open the document root of the live site (usually public_html, or a domain folder). Select the site files — for WordPress that includes wp-admin, wp-content, wp-includes, wp-config.php, and index.php.

Click Compress → Zip Archive. When the zip finishes, select it and click Download. Keep wp-config.php in the archive; you will edit database names on the destination, not on the original.

Step 6 — Export the database in phpMyAdmin

On the source cPanel: Databases → phpMyAdmin. In the left list, click the database named in wp-config.php. Open the Export tab → method Quick → format SQL → Go. Save the .sql file next to your zip.

If the database is larger than the phpMyAdmin upload limit on the destination (often 50–128 MB), ask the host to raise it, or import via SSH mysql if you have terminal access. For most brochure and content sites, Quick export is enough.

Step 7 — Create a database, upload files, and import SQL

Log in to the destination cPanel (the new site’s server).

  1. MySQL Database Wizard — create a new database, a new user, and grant All Privileges. Write down database name, user, and password. cPanel prefixes these with your account name.
  2. File Manager — open the new domain’s document root. Upload the zip, then Extract. Confirm wp-config.php sits in that root, not inside an extra nested folder. If File Manager extracted into public_html/public_html/, move the files up one level.
  3. phpMyAdmin — select the new empty database → Import → choose the .sql file → Go.
  4. Edit wp-config.php on the destination only:
define( 'DB_NAME', 'account_newdb' );
define( 'DB_USER', 'account_newuser' );
define( 'DB_PASSWORD', 'the-new-password' );
define( 'DB_HOST', 'localhost' );

Leave table prefix ($table_prefix) as it was on the source so the imported tables match. Visit the new domain. If you see the site with mixed old URLs or a redirect loop, continue to URL replace — do not reinstall WordPress on top of the copy.

Replace old URLs with the new domain

WordPress stores the site address in the database (wp_options: siteurl and home) and in serialized arrays used by page builders, menus, widgets, and many plugins. A plain Find-and-Replace in a text editor breaks those arrays. Use a tool that understands serialized PHP:

  • Better Search Replace (plugin) — run from wp-admin on the clone. Search https://oldsite.com → replace https://newsite.com. Dry run first. Include tables; skip guid unless you know you need it.
  • WP-CLI if SSH is available: wp search-replace 'https://oldsite.com' 'https://newsite.com' --all-tables --dry-run then drop --dry-run.
  • Softaculous Clone already rewrites the main options. Still run a search for the old hostname if images or internal links stay on the source domain.

Match protocol and www. If the old site was https://www.oldsite.com, search that exact string. Run a second pass for the non-www variant if both exist in the database.

After replace, go to Settings → Permalinks and click Save to flush rewrite rules. Clear any cache plugin on the clone.

After clone checklist (SSL and SEO)

A working copy is not a launched site. These steps prevent mixed-content warnings, duplicate rankings, and “Couldn’t fetch” sitemap errors.

  1. Force HTTPS on the new domain — cPanel → SSL/TLS Status → Run AutoSSL. Then confirm WordPress Address and Site Address use https://.
  2. Decide if the clone is public. Two live copies of the same content compete in Google. If this is staging or a backup URL, set Settings → Reading → Discourage search engines from indexing this site, and keep it behind a password if the content is sensitive.
  3. If the new domain is the real launch — 301 redirect the old URLs to the matching new URLs (cPanel Redirects or an .htaccess rule), submit a new sitemap, and add the new property in Google Search Console. Use Change of Address when you are retiring the old hostname.
  4. Update the XML sitemap and robots.txt on the new host so they list the new domain, not the old one.
  5. Test forms, checkout, cron, and email. SMTP plugins and API keys often still point at the old environment. Contact forms that send from the old hostname will fail SPF on the new server until you add DNS records.
  6. Speed-check the new host — TTFB and cache plugins depend on the server. Follow how to make your website load fast after the clone is stable.
Duplicate content: Google does not “merge” two clones. Either noindex the extra copy, or 301 the old domain to the new one. Leaving both indexable is the most common SEO mistake after a cPanel clone.

Fixes when the clone looks wrong

  • Redirect loop / “too many redirects” — mixed www/HTTPS in siteurl vs the server. Align both to one canonical URL, and check Cloudflare SSL mode (Flexible vs Full).
  • White screen or HTTP 500 — enable WP_DEBUG on the clone only, or check error_log in File Manager. Often a plugin path or PHP version mismatch (set MultiPHP to 8.1+ to match the source).
  • Styles and images missing — leftover old URLs, or files extracted into a nested folder. Fix the document root, then rerun search-replace including http:// and https:// variants.
  • Cannot log in to wp-admin — cookies from the old domain. Use a private window on the new hostname. If the database still has the old siteurl, set it in phpMyAdmin → wp_options.
  • Softaculous does not show Clone — the app was installed manually. Use Method 2, or import the existing install into Softaculous first (Import tab), then clone.

FAQ

Does cloning delete or overwrite the original site?

No. Softaculous Clone and a File Manager zip both copy. The source stays online. You only overwrite the original if you extract into the same document root or pick the same domain in the clone form.

Can I clone to a different cPanel server?

Yes. Softaculous Clone only works on the same account. For a new server, use Method 2: zip files, export SQL, create a database on the new cPanel, upload, import, edit wp-config.php, then search-replace URLs.

Do I keep the same WordPress admin login?

Yes. Users live in the database. After a correct import, the same username and password work on the new domain. Reset via email only after the new site can send mail.

Should I clone or install WordPress fresh?

Clone when you need the same theme, plugins, and content. Fresh install when the new site should not inherit old plugins, spam comments, or leftover SEO titles. See the cPanel WordPress install guide for a clean start.

How do I avoid duplicate content after cloning?

If the clone is for testing, noindex it. If it is the new live site, 301 the old URLs, update Search Console, and do not leave both domains serving the same pages without canonicals pointing to one winner.

Can I clone a static HTML site in cPanel?

Yes — you only need File Manager (or FTP). Zip the document root, extract it on the new domain folder, and skip MySQL. URL replace is a search in HTML/CSS files instead of a WordPress plugin.
